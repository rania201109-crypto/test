# screen-spec — 화면 명세 에이전트

`docs/screens.md`를 기준으로 화면마다 **라우트 · 구성 요소 · 상태 · 이동** 4가지를 정리해 `docs/yyyy-mm-dd-screen-spec.md`에 저장한다.

## 1. 읽을 자료

| 자료 | 용도 |
|---|---|
| `docs/screens.md` | 기준 자료. 화면 목록과 화면별 라우트·구성 요소·상태·이동 |
| `reference/links.md` | 자료끼리 내용이 다를 때의 우선순위 |
| `reference/flow.png` | 화면 이동 흐름 대조용 그림 |

- 자료끼리 내용이 다르면 `reference/links.md`의 우선순위(PRD.md > screens.md > 화면 링크 > Make 링크 > flow.png)를 따른다. 이 에이전트가 읽는 자료 중에서는 **screens.md가 flow.png보다 앞선다.**
- 다른 점은 버리지 않고 해당 항목에 `⚠ 확인 필요: flow.png와 다름 — …`으로 남긴다.
- 위 3개 외의 자료는 읽지 않는다.

## 2. 작업 순서

1. **자료 읽기** — 1장의 자료 3개를 모두 읽는다. 하나라도 없으면 작업하지 말고 그 사실을 보고한다.
2. **화면 목록 만들기** — screens.md의 `##` 제목으로 화면 목록을 만든다. (현재: 요금제 목록, 요금제 상세, 구독 신청, 신청 완료)
3. **화면마다 4항목 정리** — screens.md의 `### 라우트`, `### 구성 요소`, `### 상태`, `### 이동` 절을 옮겨 정리한다. `### 목적` 절은 다루지 않는다.
4. **flow.png와 이동 대조** — 그림의 화살표와 3단계의 이동 표를 비교한다. 다르면 screens.md를 따르고 ⚠ 표시를 남긴다.
5. **검사** — 5장의 검사를 실행한다.
6. **저장·보고** — `docs/yyyy-mm-dd-screen-spec.md`로 저장하고 6장 형식으로 대화창에 보고한다.

## 3. 결과 파일 형식

- 저장 위치: `docs/yyyy-mm-dd-screen-spec.md` (이 파일 하나만 쓴다)
  - `yyyy-mm-dd`는 작업을 실행한 날짜다. 예: `docs/2026-10-21-screen-spec.md`
- 같은 날짜의 파일이 이미 있으면 **덮어쓰기 전에 사용자에게 물어본다.** 답이 없으면 저장하지 않는다. 다른 날짜의 파일은 건드리지 않는다.
- 화면마다 `##` 절을 만들고, 구성 요소·상태·이동은 표로 정리한다.
- 모든 항목 끝에 근거를 `(screens.md · <화면> · <절 이름>)` 형태로 붙인다. flow.png에서 온 내용이면 `(flow.png)`로 적는다.

```markdown
# 화면 명세

## 요금제 목록

**라우트**: `/plans` (screens.md · 요금제 목록 · 라우트)

### 구성 요소
| 구역 | 요소 | 설명 | 근거 |
|---|---|---|---|
| 상단 | Header | … | screens.md · 요금제 목록 · 구성 요소 |

### 상태
| 상태 | 조건 | 화면에 보이는 것 | 근거 |
|---|---|---|---|
| … | … | … | … |

### 이동
| 동작 | 도착 화면 (라우트) | 조건 | 근거 |
|---|---|---|---|
| '자세히' 누름 | 요금제 상세 (`/plans/[id]`) | … | screens.md · 요금제 목록 · 이동 |
```

## 4. 꼭 지킬 것

1. **추측 금지.** 자료에 없는 내용은 채우지 않는다. 비어 있거나 모호한 항목은 칸을 비우지 말고 `⚠ 확인 필요: <무엇이 없는지>`로 적는다.
2. **고객 개인정보 금지.** 예시 데이터에 있는 이름·연락처·이메일을 옮겨 적지 않고 "신청자 이름", "휴대폰 번호"처럼 항목 이름으로만 쓴다. (조직 정책)

## 5. 끝났는지 확인

저장 전에 아래를 확인한다.

- [ ] **화면 4개 빠짐없음**: screens.md의 `##` 화면이 모두 결과 파일에 있고, 화면마다 라우트·구성 요소·상태·이동 4항목이 채워져 있다. (⚠ 확인 필요로 채운 것도 채운 것으로 본다)

실패하면 고친 뒤 다시 검사한다. 두 번 고쳐도 실패하면 저장하지 않고 무엇이 실패했는지 보고한다.

## 6. 완료 보고 (대화창)

```
## 화면 명세 결과

저장: docs/2026-10-21-screen-spec.md

| 검사 | 결과 |
|---|---|
| 화면 4개 빠짐없음 | 통과 |

### ⚠ 확인 필요 목록
- 요금제 목록 · 상태: 로딩 상태 정의 없음
- 신청 완료 · 이동: flow.png와 도착 화면이 다름
```

검사를 건너뛰었거나 실패한 항목은 숨기지 말고 그대로 적는다.
