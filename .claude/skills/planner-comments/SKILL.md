# planner-comments — 기획자용 한국어 주석

화면 코드에 **코드를 바꾸지 않고** 한국어 주석만 추가한다.
주석의 독자는 개발자가 아니라 기획자다. "이 코드가 무엇을 하는가"보다 "사용자가 무엇을 보고, 무엇을 할 수 있고, 그게 PRD의 어디에서 왔는가"를 쓴다.

## 1. 작업 순서

1. **대상 파일 정하기**
   - 사용자가 파일을 지정하면 그 파일만 다룬다.
   - 지정하지 않으면 화면 파일 4개 전체를 다룬다: 요금제 목록(`/plans`), 요금제 상세(`/plans/[id]`), 구독 신청(`/apply`), 신청 완료(`/complete`)의 라우트 파일. 라우트 파일 위치는 프로젝트 구조를 보고 찾는다.
   - 화면 파일을 찾지 못하면 작업하지 말고 그 사실을 보고한다.
2. **근거 문서 읽기**
   - `docs/PRD.md`를 먼저 읽는다. (화면 목록, 화면별 기능, 오류 문구, O/X 판정 규칙, 데이터)
   - `docs/screens.md`를 참고로 읽는다.
   - 둘이 다르면 `reference/links.md`의 우선순위(PRD.md > screens.md > …)대로 **PRD를 따른다**.
   - `docs/Design.md`는 읽지 않는다. 색·간격 규칙은 기획자용 주석의 대상이 아니다.
3. **원본 보관**
   - 작업 전에 대상 파일마다 원본 사본을 scratchpad 디렉터리(없으면 시스템 임시 폴더)에 저장한다. 프로젝트 폴더 안에는 사본을 만들지 않는다.
4. **주석 달기** — 아래 4가지 단위 모두에 단다.
   - (a) 파일 맨 위: 화면 요약 (형식은 2장)
   - (b) 화면 구역마다: Header, 필터, 카드 목록, 입력 영역, 하단 버튼 영역 등
   - (c) 동작마다: 버튼을 누르면 어디로 가는지, 입력 검증, 저장
   - (d) 상태·조건마다: 버튼 비활성 조건, 오류 문구가 나오는 조건, 할인 없을 때 숨김 등
   - 이미 있는 주석은 그대로 두고 새 주석만 추가한다.
5. **확인** — 5장의 검사를 모두 실행한다.
6. **보고** — 6장의 형식으로 대화창에 보고한다. 보고서 파일은 만들지 않는다.

사용자에게 미리 승인받지 않고 바로 단다. 대신 5장 검사로 코드가 바뀌지 않았음을 증명한다.

## 2. 주석 형식

### 파일 맨 위 — 화면 요약 (10줄 이내, 형식 고정)

```
/**
 * [화면] 요금제 목록
 * [목적] 데이터량·소진 후 속도·매달 내는 금액을 한 카드에서 비교해 후보를 고르게 한다.
 * [라우트] /plans
 * [들어오는 곳] 서비스 진입
 * [나가는 곳] 카드의 '자세히' → 요금제 상세(/plans/[id])
 * [근거] PRD 3장·4-1 · US1, US2, US3, US4
 */
```

### 그 밖의 주석 — 한두 줄, 짧은 서술체

```
// 할인이 없는 요금제는 '25개월째부터 ○원' 줄을 숨긴다. (US4 · PRD 4-1)
// 이름·휴대폰 번호·동의 중 하나라도 없으면 '신청하기'가 눌리지 않는다(disabled). (US5 · PRD 4-3)
// ⚠ 확인 필요: 실습용 임시값. 추천 기준이 정해지지 않았다. (PRD 4-1)
```

- 근거는 `(US번호 · PRD 절번호)` 형태로 끝에 붙인다. 근거가 없는 주석이면 생략하지 말고 ⚠ 확인 필요로 바꾼다.
- PRD에서 "확인 필요"인 항목(추천 기준, 필터 칩 항목, 기본 정렬, 완료 화면의 이동 목적지, 포함 혜택, 뒤로 갈 때 입력값 유지, 로딩·빈·에러 상태)이 코드에 임시값으로 들어가 있으면 반드시 `⚠ 확인 필요`를 붙인다.

### 주석 문법 — 파일 종류별

| 위치 | 쓰는 문법 |
|---|---|
| JS/TS 코드 (함수, 변수, 조건문 위) | `// …` 또는 `/** … */` |
| JSX/TSX 태그 사이 | `{/* … */}` 만 쓴다. `//`를 쓰면 화면에 글자로 그대로 보인다 |
| HTML·Vue `<template>` | `<!-- … -->` |
| CSS | `/* … */` |

- 주석은 **항상 별도 줄**에 쓴다. 기존 코드 줄 끝에 붙이지 않는다(검사 스크립트가 줄 단위로 비교하기 때문).
- 여러 줄 주석은 각 줄을 ` * `로 시작한다.
- 들여쓰기는 바로 아래 코드 줄에 맞춘다.

## 3. 꼭 지킬 것

1. **코드 변경 금지.** 기존 코드는 한 글자도 바꾸지 않는다. 줄바꿈, 들여쓰기, 따옴표, 세미콜론, 빈 줄 정리도 모두 금지. 추가하는 것은 주석 줄뿐이다.
2. **쉬운 말 먼저.** 개발 용어는 필요할 때만 괄호로 붙인다. 예: "화면이 기억하는 값(state)", "눌리지 않음(disabled)", "다른 화면으로 이동(navigate)".
3. **쓰면 안 되는 내용**
   - 고객 개인정보. 시안·예시 데이터에 있는 이름·연락처·이메일도 주석에 옮겨 적지 않는다. "신청자 이름", "휴대폰 번호"처럼 항목 이름으로만 쓴다.
   - PRD·screens.md에 없는 추측. 근거가 없으면 `⚠ 확인 필요`로 적는다.
   - 실제 통신사 요금제와의 비교. 요금제 데이터는 실습용 가상 데이터다.
4. **말투**: 짧은 서술체("~한다", "~함"). 존댓말을 쓰지 않는다.
5. **양 제한**: 화면 요약은 10줄 이내, 그 밖의 주석은 2줄 이내. `import`, 단순 스타일 지정, 의미 없는 감싸는 태그처럼 뻔한 곳에는 달지 않는다.

## 4. 주석에 담을 내용 (기획자 관점)

- 사용자가 **보는 것**: 어떤 정보가 어떤 조건에서 나타나고 숨는지
- 사용자가 **하는 것**: 누르기·입력하기 → 그 결과(이동, 저장, 오류 문구)
- **규칙의 출처**: PRD의 유저 스토리(US1~US5)와 절 번호, O/X 판정 규칙 번호(예: "판정 규칙 3")
- 코드 내부 구현 방식(어떤 훅을 쓰는지, 왜 이 라이브러리인지)은 쓰지 않는다.

## 5. 끝났는지 확인

모든 대상 파일에 대해 아래 3가지를 실행한다.

1. **코드 변경 검사** — 원본 사본과 비교한다.
   ```bash
   node .claude/skills/planner-comments/scripts/check-comments-only.mjs <원본 사본> <수정한 파일>
   ```
   - 원본의 모든 줄이 순서대로 그대로 남아 있고, 추가된 줄이 모두 주석 줄이면 통과.
   - Node가 없으면 같은 기준으로 직접 비교하고, 스크립트 대신 수동 비교했다고 보고한다.
   - 스크립트는 JSX 안의 `//` 오류를 잡지 못한다. 추가한 `//` 줄이 JSX 태그 사이에 있지 않은지 직접 한 번 더 확인한다.
2. **빌드 확인** — `package.json`에 `build` 명령이 있으면 실행한다(`npm run build` 등). 없으면 건너뛰고 "빌드 명령 없음, 건너뜀"이라고 보고한다.
3. **빠짐없이 달렸는지 확인** — 화면마다 체크한다.
   - [ ] 파일 맨 위에 화면 요약 1개가 있다
   - [ ] PRD 4장의 해당 화면 "필수 기능" 항목마다 주석이 1개 이상 있다
   - [ ] 코드에 들어간 "확인 필요" 임시값마다 `⚠ 확인 필요` 표시가 있다

**실패했을 때**: 고칠 수 있으면 고친 뒤 다시 검사한다. 두 번 고쳐도 실패하면 그 파일을 원본 사본으로 되돌리고, 무엇이 실패했는지 보고한다.
